\## Business context

You will create a skill to act as an analytics copilot on the Olist database. A marketplace team needs to investigate orders, sales, and customers through natural-language questions. The agent must query the data, execute code, and explain the results in a verifiable way.

Use the Olist CSVs and the dictionary dicionario.xlsx provided by the professor. The database includes pedido.csv, cliente.csv, item\_pedido.csv, pagamento\_pedido.csv, produto.csv, vendedor.csv, and avaliacao\_pedido.csv. Select the files needed for each question and preserve the original data.



\## Proposed activity

Create a skill, with a name such as analise-olist, that guides the agent to understand the question, identify tables and fields, clarify ambiguities, write or reuse Python code, execute the query, and present the answer. The conversation with the agent will be the interface of the activity; it is not necessary to develop a new dashboard, chatbot, or MCP server.

The skill must support the analyses below and accept period changes requested in the conversation:

\- How many delivered orders were placed in each month?

\- What are the five customer UFs with the most delivered orders?

\- What was the average ticket of item prices per delivered order, excluding freight?

After obtaining an answer, make a follow-up request, such as restricting the period or filtering a UF. The agent must interpret the change, re-execute the code, and explain the new result. The answers must result from the files queried and the filters applied, without numbers hardcoded in the code or in the skill text.



\## Building the skill

Use the brainstorm and the SKILL.md template provided in class. Define the task, inputs, rules, and completion criteria before adapting the template. The final version must reflect Olist, without forgotten placeholder fields.

\- SKILL.md: include name and description in the YAML metadata and describe when to use the skill, inputs, procedure, checks, response format, and limitations. Guide the agent to execute the code before presenting values as calculated.

\- references/: record the business rules, metrics, and relationships needed. Make SKILL.md indicate when to consult these references.

\- scripts/: keep the reusable code needed for the analyses. Allow configuring the data folder and the filters. State dependencies and commands to run and verify the work.

Place the skill folder in the location recognized by the chosen agent. In the local Codex project, use .agents/skills/skill-name/; in local Claude Code, .claude/skills/skill-name/. Activate the skill and confirm that it is read. PRD.md, SPEC.md, or AGENTS.md are not required for this deliverable.



\## Rules and validation

Consider orders with descSituacao equal to delivered and use dtPedido as the reference date. Count distinct idPedido. For the UF ranking, relate pedido and cliente by idCliente and use descUF. The average ticket is the sum of vlPreco of the items of the selected orders divided by the number of distinct selected orders, excluding vlFrete. Explain the coverage if there are orders without items.

Check the keys in the dictionary. An order can have multiple items and multiple payments: avoid multiplying values when combining tables. Differentiate item price, freight, and vlPagamento. Declare the handling of missing data, invalid dates, and unmatched keys. State the period and the convention adopted for your start and end dates.

Execute the three questions and the follow-up request. Check two analyses on a small subset with expected results calculated independently. Also test a period with no data and a question the database cannot answer. A count with no orders is zero; an average with no orders is not applicable.

Each answer must state the metric, the filters, the files used, and the result. Show the executed code or its path, the command, and the relevant output. When access is missing or a failure occurs, the agent must explain the impediment. Review the decisions and code generated by the AI and record the changes on GitHub, using branches and PRs.
