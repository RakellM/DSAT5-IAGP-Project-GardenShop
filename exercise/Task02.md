\## Business context



Continue the Garden Shop inventory dashboard proposal developed in Class 1. The online gardening products store needs to identify products that require attention, track sales, evaluate inventory value, and relate items to suppliers. In this activity, you will document and implement the solution with the support of generative artificial intelligence.  

Use the files products.csv, categories.csv, suppliers.csv, orders.csv, order\_items.csv, and customers.csv and the garden\_shop\_data\_dictionary.xlsx provided in Class 1. Select only the tables and fields needed and preserve the original data.  

Cancelled orders do not count as effective sales. Define the treatment of pending, processing, and shipped. Discontinued products must not receive automatic replenishment recommendations. quantity\_on\_hand represents current inventory; there is no movement history or supplier delivery lead time. Differentiate the sales period from the current inventory position and avoid duplicating balances or values when relating products and order items.



\## Proposed activity



Implement a functional version of the dashboard with at least two indicators, one filter, and a table or chart useful to the business. Revise the scope of the previous proposal when necessary, maintaining coherence between the problem, the data, and the delivered solution.  

Follow the process discussed in Class 2: understand the problem, brainstorm with the AI, write the PRD, validate the requirements, produce the SPEC, implement, and test. Check the requirements against the data dictionary and the expected result examples before starting the code.  

Create the GitHub repository at the beginning and implement small parts in branches, opening PRs to review and integrate the changes. Use the SPEC as a living reference. Update the documents when a discovery changes the expected behavior. Work with the AI as a partner: guide the objective, question proposals, and review the changes.  

For the calculation rules, define the expected result and write tests before implementation. Run the tests and check the application before integrating each part. Validate two indicators with calculations made on a small subset of the CSVs. Check cancellations, discontinued products, products with no sales, filters with no results, and relationships that could duplicate inventory.  

Prepare the three Markdown files below for the implemented project:

\- AGENTS.md: instructions for the agent to work in the repository, documents to consult, environment setup, execution and test commands, code organization, and data care. Guide the review of changes and the updating of documents. Identify commands not yet verified.

\- PRD.md: problem, user, objectives, scope, and exclusions. Describe the indicators, filters, and visualizations and justify their usefulness. Define business rules and observable acceptance criteria, including for situations with no data. Identify the requirements to reference them in the SPEC.

\- SPEC.md: inputs, outputs, tables, fields, keys, formulas, aggregations, filters, and exclusions. Define error handling and missing values, replenishment rule, prevention of duplications, and module responsibilities. Include examples with expected results and rule checks. Keep the specification aligned with the final dashboard.  



Review the content generated by the AI. The documents must explain your decisions and correspond to the implemented code. The instructions to install, run, and test the project may be in AGENTS.md.
